Chapter 01

The gap between Agent Evaluations and real adversaries

UiPath Agent Evaluations tell you whether your agent passes the tests you wrote. They don't tell you what happens when a real attacker shows up with a prompt you never imagined.

Agent safety today is mostly vibes-based. Teams ship an agent, write a few eval rubrics, and hope nothing breaks. Gauntlet replaces "hope" with a continuous adversarial loop.

TodayWith Gauntlet
Static eval rubrics that humans wroteSelf-play that invents new evals
"Did we test prompt injection?" → maybe?OWASP / MITRE coverage matrix on every release
Bug found in prod → manual repro → manual test caseAuto-populated Test Manager regression entry
Failure → developer manually patches promptFix Recommender drafts the patch, opens Action Center task
"The interesting evals are the ones the human didn't write. Self-play creates evals you'd never think to author."

The rest of this manual walks through how that loop runs end-to-end inside your UiPath tenant.

Chapter 02

A continuous adversarial loop

A Red Coach agent plays an adversary against any UiPath Agent, Maestro Flow, or external target. Winning attacks become permanent regression tests. Failing fights become Action Center tickets.

The four pillars

1 · Red Coach invents attacks

Picks the highest expected-reward persona via Thompson sampling, or asks a frontier LLM to author a new one mid-fight.

2 · Test Manager grows itself

Every winning attack auto-persists as a Test Manager case. The regression suite is the byproduct of the loop.

3 · Fix Recommender drafts patches

On a Blue loss, a second agent reads the transcript and proposes a concrete remediation. An Action Center task lands in the reviewer's queue.

4 · Coverage you can audit

Every fight double-tagged against OWASP LLM Top-10 and MITRE ATLAS. The audit view renders coverage as a matrix a compliance officer can read.

The system under test

The reference Blue target shipped with Gauntlet is MetroBankCSR, an Agent Builder agent that plays a bank customer-service rep. Swap it for any UiPath Agent, Maestro Flow, or external LangGraph target. The arena is framework-neutral.

Chapter 03

How it works

Gauntlet is structured as a long-running Maestro Case with rounds-as-tasks. Each round is one Maestro Flow execution that pits Red against Blue.

Round lifecycle

┌─────────┐    ┌──────────────┐    ┌─────────┐    ┌──────────┐
│ Matched │ →  │ Negotiating  │ →  │ Verdict │ →  │ Archived │
└─────────┘    └──────────────┘    └─────────┘    └──────────┘
                     │  ▲                  │
                     │  │ multi-turn       │
                     │  │ exchanges        ▼
                     └──┘            Coach updates
                                     Test Manager;
                                     Fix Recommender
                                     opens an Action
                                     Center task on
                                     a Blue loss.

Coach self-play loop

  1. Pick the Red persona with the highest expected risk-weighted reward against this Blue target (Thompson sampling).
  2. If no persona has a positive expected reward, ask a frontier LLM to author a new one, conditioned on the last K losing transcripts.
  3. Run the round.
  4. On Red win: persist persona + transcript to Test Manager as a regression test.
  5. On Blue loss: update reward priors. Loop.

This is what makes the test suite grow without humans. The corpus is the byproduct of the Coach trying to maximise successful attacks.

Comprehensive component reference

Gauntlet ships as a UiPath solution combining Coded Agents and Low-code Agents, proving the arena is framework-neutral.

ComponentRole
Maestro Case · FightArenaLong-running fight orchestration. Rounds as tasks. Stages: Matched → Negotiating → Verdict → Archived.
Maestro Flow · RoundOrchestratorSingle round end-to-end. Red attack → Blue response → judge → score.
Agent Builder · MetroBankCSRThe Blue target. Reference customer-service agent.
Agent Builder · RefereeAgentIn-tenant judge. Scores each round against the rubric.
Coded Agents (Python, LangGraph)Red Coach (gauntlet coach) and Fix Recommender (gauntlet fix).
Coded App · gauntletappOperator surface. React + @uipath/uipath-typescript SDK. Hosts Dashboard, Coach Lab, Fix Lab, Analytics, Audit, Logs.
Test ManagerPersistent regression set. Auto-populated by the Coach on winning attacks.
Action CenterHuman-in-the-loop fix approval. Tasks opened from the Fix Lab.
UiPath TypeScript SDKBrowser-side calls to Maestro instances, Test Manager, Action Center.
UiPath Automation CloudExecution and orchestration plane. Tenant: thesingularityisnearer / DefaultTenant.
uip CLI 1.0.4+Login, package, publish, deploy across all artefacts.

Agent type declaration

Both Coded Agents and Low-code Agents. Coach and Fix Recommender are Python coded agents. MetroBankCSR and RefereeAgent are low-code Agent Builder agents. FightArena and RoundOrchestrator are low-code Maestro orchestration.

Coach Lab

The Coach picks the persona × posture with the highest expected reward, or asks a frontier LLM to invent a new attack live in front of you.

  1. Read the risk-weighted coverage table. The Coach highlights where Blue is weakest. The gap column is the expected reward delta.
  2. Paste an API key. Stays in sessionStorage. Never leaves your browser.
  3. Click "Run live (add key)". A frontier LLM authors a fresh attack persona right now. Watch it render below the table.
  4. The persona enters rotation. The next fight will be eligible to draw the new persona.

08 · Fix LabOperator Manual · v1.0
Chapter 08 · Walkthrough

Fix Lab

Diagnose a losing fight and file the remediation as an Action Center task in two clicks.

What the Fix Recommender produces

  • Root cause. A diagnostic written against the transcript, including the exact turn that broke policy.
  • Suggested patch. A concrete system-prompt edit, tool-scope restriction, or guardrail rule.
  • Regression test. The proposed Test Manager entry that should be added so this defect cannot recur silently.
  • Confidence score. A self-reported certainty on whether the proposed patch will hold against the same persona.

One click on File to Action Center creates a real Action Center task in your tenant, with the patch text pre-populated and the original fight transcript attached as evidence.

Audit

Posture and compliance. What we cover against the AAA spec, ISO 42001, and the NIST AI RMF.

Six audit cards, each showing a category of adversarial testing applicable to this agent. For each, you see whether we cover it today (green), partially cover it (amber), or have it on the roadmap (blue). Numbers come from the live corpus, not a static checklist.

What you get for a compliance review

  • Direct, indirect, and crescendo prompt-injection coverage with attack success rates.
  • Tool-use integrity and action-integrity scores, with policy violations counted.
  • Robustness and regression evidence across four blue postures plus the external target.
  • Multi-agent orchestration security probes if Blue is a graph rather than a single agent.
  • Real-time SIEM streaming and Action Center triage if Reporting & Observability is enabled.

Chapter 11 · Walkthrough

Logs

Every adversarial call ever run, searchable and filterable. Click any row to read the full transcript.

How to read the table

  • Started: ISO timestamp.
  • Persona / Scenario: the Red configuration.
  • Blue mode: Standard, Lenient, Naive, or External.
  • Outcome: Blue Wins, Red Wins, or draw.
  • AVS / REB / Turns: Adversarial Vulnerability Score, Referee Evidence Body, exchanges before verdict.
  • Fix proposal: queued, proposed, applied, or none.

Use the search box to filter on persona, scenario, or AVS threshold. Use View fix to jump straight to the patch.

Chapter 12

Setup and deployment

Six steps to a working Gauntlet tenant. Designed for a judge to follow from a cold clone.

Prerequisites

  • UiPath Automation Cloud tenant with Test Cloud, Maestro, Agent Builder, Action Center, Coded Apps, and Test Manager enabled.
  • Node.js 20+, Python 3.11+, uip CLI 1.0.4+.
  • A frontier-model API key.

1 · Clone and configure

git clone https://github.com/tdries/uipath-hackathon-gauntlet.git
cd uipath-hackathon-gauntlet
cp .env.example .env

2 · Authenticate, install Python package

uip login
python -m venv .venv && source .venv/bin/activate
pip install -e .

3 · Deploy the UiPath solution and Coded App

cd uipath/gauntlet
uip solution publish gauntlet.uipx
uip solution deploy --name gauntlet

cd ../gauntlet-console
npm install && npm run build
uip codedapp publish

4 · Run the demo workflow

Open gauntletapp in the Apps tab, click Run a fight, then visit Coach Lab, Fix Lab, Audit, and Logs.
